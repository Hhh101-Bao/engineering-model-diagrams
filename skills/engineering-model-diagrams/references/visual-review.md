# 成图审查

1. 比对实际模型与源 JSON，核对分支、残差、拼接轴、输入输出和贡献模块。展开图必须来自已知定义。演示样例不是用户的真实模型。
2. 检查 `.check.json`：结构、几何、文字边界、端口、连线穿过节点/文字/组标题及最终字号。算子尺寸不完整的提示需要人工处理。
3. 查看最终 PNG，必要时对 PDF 用 pdftoppm 重渲染。检查中文缺字、长标签、图例、线型、留白与阅读顺序。自动检查没有覆盖全部线线交叉、数学关系和视觉层次。
4. 在期望物理宽度下阅读，不只在放大窗口查看。灰度模式需保留节点标签与算子符号，不能仅靠颜色辨别。
5. 图形检查失败就修正并重跑；对复杂路径优先用明确的固定布局约束。通常几次局部修复足够；持续失败时保留诊断并说明未解决之处，不能无限循环或称为已通过。

`--allow-issues` 仅用于生成待修复的诊断图，不得将其作为验收通过。交付时报告已验证范围；没有真实对照实验时，避免声称全面超过原项目。配色对照只验证风格变化，不验证原项目整体布局能力。
